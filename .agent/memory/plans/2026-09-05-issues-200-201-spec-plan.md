# Plan — Spec e implementación de Issues #200 y #201

## Contexto

Dos hallazgos de fricción real detectados en sesión 2026-09-05 (worktree `org-config-phase1`,
repo `Ebi-Chile/ti-github-conf`), ya registrados como issues en `aura-agent-kit` con hipótesis
P4 pre-escritas, pero sin spec formal ni plan de implementación:

- **Issue #200** — un worktree nuevo no inicializa el submódulo `.aura`, así que el protocolo
  blando del harness (`session_start.md`, router, reglas) no carga, **sin ningún error
  visible**. Solo lo duro (hooks en `.claude/hooks/`) sigue protegiendo. Nadie lo nota salvo que
  pregunte explícitamente.
- **Issue #201** — no hay forma barata de saber, mirando un listado de repos, cuáles son
  personales, cuáles son en copropiedad con una empresa, ni de qué trata cada uno (frontend /
  backend / automatización / ML / etc.) sin abrir cada repo.

Una revisión adicional del usuario, tras la primera versión de este plan, agregó cuatro
requisitos que cambian el diseño de fondo (ver "Decisiones ya tomadas" y el punto crítico sobre
dónde vive la garantía de que el protocolo se ejecute).

---

## Hallazgo crítico de esta ronda: dónde se rompe la garantía del protocolo

Investigado `install.sh`/`install.ps1`: el `CLAUDE.md` que queda en la **raíz** de un repo
consumidor contiene **únicamente**:
```
<!-- aura:begin -->
@.aura/CLAUDE.md
<!-- aura:end -->
```
Es decir, el `CLAUDE.md` raíz no tiene ningún texto propio — es solo un import. Y
`.aura/CLAUDE.md` (que es este mismo repo, clonado como submódulo) es el que contiene la
instrucción "OBLIGATORIO: Leer y ejecutar `protocols/session_start.md`" — pero esa ruta, resuelta
desde dentro de `.aura/CLAUDE.md`, apunta a `.aura/protocols/session_start.md`.

**Consecuencia:** si `.aura` no está inicializado, no solo se pierde el protocolo — se pierde
la instrucción que dice "hay que seguir un protocolo". No existía, en ningún archivo que viva
fuera de `.aura/` (por lo tanto garantizado presente siempre), una sola línea que diga "este repo
usa el harness Aura, verificalo antes de continuar". Esto es lo que el usuario señaló como
faltante en la v1 de este plan, y es el fix de más alto apalancamiento de los cuatro.

---

## Decisiones tomadas

**Issue #200:**
1. `session-start.ps1` (que SÍ corre siempre, vive fuera de `.aura/`) auto-ejecuta
   `git submodule update --init .aura` cuando detecta el gitlink sin inicializar (fail-open).
2. El `CLAUDE_ENTRY` de `install.sh`/`install.ps1` gana una línea de texto literal, propia del
   archivo raíz, fuera del import — garantiza que "hay que seguir un protocolo" sobreviva aunque
   `.aura/` esté vacío.
3. Default recomendado en `AGENTS.md`/`protocols/router.md`: preferir ramas
   (`new-branch-for-issue.sh` + PR) para trabajo cotidiano.
4. `agents/github.md` gana la "Regla anti-worktree": si `session_start.md` Paso 3 detecta un
   worktree abierto además del checkout activo, propone eliminarlo (con confirmación previa).

**Issue #201 (alcance ampliado — 3 dimensiones de topics, no solo ownership):**
1. Documentar la convención en `agents/github.md` + script de auditoría.
2. Ownership (`personal` / `<empresa>-copropiedad`) + Dominio/stack (`frontend`, `backend`,
   `automation`, `ml`, etc.).
3. Convención de nombre de repo nuevo (`<empresa>-<proyecto>`) — solo repos nuevos, nunca
   renombrar existentes.
4. `session_start.md` Paso 6 reporta ahora nombre + topics del repo activo (decisión explícita
   del usuario, contradice la exclusión de alcance original del issue).

## Implementación (completada)

- **PR #202** (Closes #200): auto-init de `.aura`, línea literal en `install.sh`/`install.ps1`,
  default ramas-sobre-worktrees en `AGENTS.md`/`router.md`, regla anti-worktree en
  `agents/github.md` + detección en `session_start.md` Paso 3, script
  `skills/repo-integrity/scripts/verify-issue-200-fixes.sh`.
- **PR #203** (Closes #201): sección de convención en `agents/github.md`, reporte de
  nombre/topics en `session-start.ps1` + `session_start.md` Paso 6, script
  `skills/repo-integrity/scripts/audit-repo-topics.sh` (verificado contra la cuenta real: 48
  repos, hallazgos sensatos), script
  `skills/repo-integrity/scripts/verify-issue-201-fixes.sh`.

Specs completas en `docs/aura/specs/2026-09-05-issue-200-worktree-aura-autoinit.md` y
`docs/aura/specs/2026-09-05-issue-201-github-topics-convention.md` (ambas locales, gitignored
por política del harness).
